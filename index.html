Abstract

TL;DR We treat a recaptioned corpus as a supervision distribution set by its captioning policy, captioner and source corpus, and audit it at a text budget of B = 64 with a five-axis profile whose common claim unit is the controllable basic unit (CBU), re-asked against the paired image by two judges from different model families and verified by human annotators on sampled claims.

Recaptioned image-text corpora are now standard for text-to-image (T2I) training, with vision–language model (VLM) captioners replacing sparse alt-text by dense descriptions. A recaptioned corpus is a supervision distribution induced by a documented captioning policy (π), captioner (Vc), and source corpus (C). Length-correlated proxies miss caption-register artifacts and downstream T2I benchmarks entangle the corpus with training choices, so this distribution is hard to audit at corpus scale. We introduce a reusable matched-budget audit framework for recaptioned supervision distributions Dπ,Vc,C: at a fixed text budget of B = 64 it reports a five-axis profile spanning prompt-side coverage, image-conditioned faithfulness, and caption-surface health, with claimed controllable basic units (CBU) as the common claim unit. We instantiate the framework on seven paired comparisons over five public source corpora. Across the four cross-corpus pairs, the released surface raises supported CBU per caption by to under both Qwen and Gemma Judges, and on CC12M the same framework exposes a long-vs-dense frontier that is consistent across both judges and four budgets. We release the audited multi-source recap corpus () together with the audit-artifact bundle.

What the audit measures

The framework is a corpus-agnostic audit operator with a fixed text budget and five axes of prompt-side coverage, image-conditioned faithfulness, and caption-surface health. Its target is a documented operating point Dπ,Vc,C: the joint over caption c and source image x induced by captioner Vc under policy π on source corpus C. Each caption set over the same source rows is a surface.

Our policy injects the register of user prompts by one simple rule: write the caption as a user writes a prompt, from the dominant subject through scene structure to camera framing. We release the resulting multi-source recap corpus as one such audit target and pair its caption set against public reference surfaces. With the captioner fixed, this policy alone raises supported CBU per caption by over a plain detailed-caption instruction (captioner control).

The audit reads the supervision signal a text-to-image model would consume, before any generator is trained. It runs four passes over source-aligned rows: it cuts every caption to the text budget B, computes deterministic text statistics on the resulting window, extracts the CBUs the window states, and re-asks each CBU against the paired image.

Controllable basic units

A CBU is a caption claim of one of eight semantic visual-claim types: object, attribute, relation, count, style, camera, lighting and text-rendering. The extractor finds CBUs caption-only and the judge re-asks each one against the paired image; CBUs serve as the common claim set behind claimed density, supported yield and unsupported risk. With c≤B the B-word window of caption c and ℓ(·) its length in lexical units:

Claimed density CBU/cap(Dc, B) = 𝔼c∼Dc[ |φ(c≤B)| ] (1)
Lexical efficiency CBU/100 lex(Dc, B) = 100 · 𝔼c[ |φ(c≤B)| ]𝔼c[ ℓ(c≤B) ] (1)
Risk ρ(Dcx) = 𝔼[ u(c, x) ] / 𝔼[ |φ(c)| ]

Supported yield and risk read the same (claim, image) pairs: yield counts the claims the Judge finds supported by the image, and risk ρ is the share it answers no for, with u(c, x) counting those claims. Risk aggregates captioner, extractor, and Judge errors.

Two judges, one question schema

The captioner Vc is Qwen3.5-35B-A3B-FP8. The extractor φ and the Qwen Judge share Qwen3.5-397B-A17B-FP8; the Gemma Judge is Gemma-4-31B-IT. Both Judges are open-weight VLMs served locally with deterministic, schema-constrained answers across all eight claim types. The Qwen Judge is the 397B-parameter checkpoint of the captioner’s family and also serves as the extractor; the Gemma Judge comes from an independently trained family and re-asks the same extracted claims, so agreement between the two Judges is agreement across model families. Each CBU becomes one of three questions:

Is the visual claim '<TARGET>: <UNIT>' supported by the image?
Is the visual claim '<UNIT>' supported by the image?
Is the rendered text claim '<UNIT>' visibly supported by the image?

Human verification

Human verification matches the judges

annotators, blind to surface identity and machine labels, judged sampled CC12M claims first against the caption window and then against the image. The verification holds primary judgments on claims; claims carry two independent labels.

Released captions

The corpus is a Hugging Face collection of our generated captions for nine source families, joined by row-level keys to the source releases that hold the images and the reference recaptions.

The code repository carries the audit pipeline, the CC12M and DataComp naive-control surfaces, and the result summaries behind every table. Captions are released as generated and caption-only, so each training pipeline applies its own personal-information, safety, NSFW, and dedup filters; every dataset card gives a removal channel through the repository's discussion page. Caption generation cost H200 GPU-hours.

Reproduce the profile

The audit is corpus-agnostic. A third party supplies caption text, source-row identifiers and, for the image-conditioned axis, paired image access; the released tokenizer, prompt pools, CBU schema, question template, label schema and manifest are reused as they are.

  1. Step 1

    Install and load captions

    The code uses uv and Python 3.11 or newer; uv.lock pins every dependency.

    git clone https://github.com/BootsofLagrangian/audit-recap-t2i.git
cd audit-recap-t2i
uv sync

    Captions stream from the Hugging Face collection, one dataset per family:

    from datasets import load_dataset

captions = load_dataset(
    "BootsofLagrangian/cc12m-recap-qwen3p5-35b-a3b",
    split="train", streaming=True)

  2. Step 2

    Text statistics and prompt pools

    Build the paired slices and the seven prompt pools, then run run_caption_fair_slice_surveys.py for the surface descriptors and caption_prompt_support_bootstrap.py for prompt-mass support and n-gram JSD.

    uv run python scripts/build_caption_fair_slices.py --all \
  --max-pairs 1000000 --seed 0
uv run python scripts/prepare_prompt_pools.py \
  --output-root data/prompt-pools/2026-04-24-expanded

  3. Step 3

    Claims and two judges

    Serve the extractor, build one request per caption window, and run it with run_text_json_requests.py; summarize_cbu_responses.py reports CBU/cap and CBU/100 lex. build_grounded_cbu_verify_requests.py attaches the images, build_cbu_vqa_requests.py and run_cbu_vqa_requests.py ask the questions, and summarize_cbu_vqa_responses.py reports supported CBU per caption and risk. The Gemma Judge answers the same request file with --model google/gemma-4-31B-it.

    bash scripts/vllm/serve_397b.sh start
uv run python scripts/build_caption_cbu_requests.py --input <surface>.jsonl \
  --output artifacts/cbu/<name>.requests.jsonl --surface <surface> --token-budget 64
